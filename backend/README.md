# Сервер сохраняет проверенные версии портфеля из Google Sheets

Google Sheets остаётся местом редактирования инициатив, сроков, исходных показателей и расчётных параметров. FastAPI читает согласованный поток каждые 15 секунд и сохраняет целый срез в PostgreSQL. React получает портфель через API – программный интерфейс сервера

Текущий публичный сайт размещается на GitHub Pages и читает Google Sheets непосредственно. Локальный сервер и комплект контейнеров подготовлены для подключения отдельного серверного адреса. Владелец выбирает место размещения серверной части

## Проверка источника сохраняет целостность портфеля

Таблицы `versions`, `current_snapshot`, `initiatives` сохраняют историю, текущую версию и карточки с уникальными кодами. Одна транзакция записывает новый срез и переключает указатель актуальной версии. Проверка целиком отклоняет поток при ошибке исходной ячейки, повторе кода, нарушении числового формата, отсутствии паспортного поля или неполном составе строк

Последний корректный срез продолжает выдаваться при сбое загрузки. Метка `source_status` содержит время проверки, состояние источника, номер версии и SHA-256 – контрольную сумму среза. Значения пустых финансовых полей сохраняются как `null`; экран показывает потребность в расчёте и согласовании

Порог полноты составляет 190 карточек. Текущий состав включает 200 карточек: 172 проекта исходных реестров и 28 новых идей. История объединения сохраняет 12 прежних кодов. Изменение порога при следующем пересмотре состава выполняет администратор через `PMO_SOURCE_MIN_RECORDS`

## Четыре маршрута обслуживают сайт и личный расчёт

| Маршрут | Результат |
|---|---|
| `GET /api/health` | Доступность PostgreSQL и состояние чтения Google |
| `GET /api/portfolio` | `{portfolio, synced_at, source_status}`, контрольная сумма `ETag` |
| `GET /api/calculators/source` | Производственный ввод Google, источники, схема и отдельный учебный пример |
| `POST /api/calculations/production` | Личный расчёт двух состояний и пяти факторов изменения EBITDA |

EBITDA обозначает прибыль до процентов, налогов и амортизации. Модель отдельно выдаёт оценочный результат и согласованный результат. Признаки подтверждения источников, расходов, спроса и мощностей определяют допуск согласованного эффекта

Признак `expenses_confirmed` означает, что финансы проверили переменные ставки, сопоставимый период и покрытие продукции, а также однократный учёт логистики и ручных переносов

Личный расчёт принимает объект `ProductionInputs` из `data/production_input_schema.json`. Ограничение запроса – 256 КБ, глубина – 16 уровней, список – 500 строк. Некорректный ввод получает код 422, превышение объёма – 413. Учебный пример хранится отдельно в `data/production_example.json`

## Локальная проверка использует свою PostgreSQL

Создайте окружение `python3 -m venv .venv` и установите зависимости `.venv/bin/pip install -r requirements.lock.txt`. Задайте `DATABASE_URL` с адресом своей базы

```sh
.venv/bin/uvicorn app.main:create_app --factory --host 127.0.0.1 --port 8000 --workers 1
```

`PMO_TEST_DATABASE_URL` задаёт отдельную базу для интеграционных проверок. Команда `.venv/bin/python -m unittest discover -s tests -v` проверяет модели, целостность источника и атомарную запись. Проверки создают отдельную схему и удаляют её после выполнения

## Контейнеры сохраняют базу и открывают API локально

Скопируйте `.env.example` в `.env` и задайте пароль `POSTGRES_PASSWORD` из 64 случайных шестнадцатеричных знаков. Локальный `.env` исключён из Git. Генерация пароля:

```sh
python3 -c 'import secrets; print(secrets.token_hex(32))'
```

Запуск комплекта:

```sh
docker compose up --build -d
docker compose logs api
```

PostgreSQL доступна API внутри отдельной сети. Её порт сохраняется внутри контейнерного комплекта. API публикуется на `127.0.0.1:8000`. Том `pmo_database` хранит версии после перезапуска. Перед размещением с внешним доступом владелец добавляет HTTPS, резервное копирование и точный адрес сайта в `CORS_ORIGINS`

Том PostgreSQL 18 монтируется в `/var/lib/postgresql` согласно [официальному описанию образа](https://github.com/docker-library/docs/blob/master/postgres/README.md#pgdata)

Допустимый источник закреплён за согласованным идентификатором Google Sheets и вкладкой `Данные сайта`. Сервер получает источник по HTTPS с ограничением 32 МБ и тайм-аутом 12 секунд. Загрузку выполняет один процесс синхронизации; запуск задаёт `--workers 1`

## Обновление структуры согласуется с React

Рабочая версия читает `../frontend/src/data/live-config.js`. Контейнер использует его проверенную копию `data/live_config.json`. После изменения диапазона потока и добавления блока калькулятора администратор переносит конфигурацию и запускает интеграционную проверку перед сборкой контейнера

Нативный ввод калькулятора хранится в `Калькулятор EBITDA!K2`, вкладка `807030034`, ключ потока `productionInputJSON`. Преобразователь возвращает его как `source_inputs.production_input`. Карточки используют 58 паспортных полей, происхождение значений и сроки L1–L5 с учётом фактического состояния проекта. Цифровой уровень Ц0–Ц5 показывает предмет изменения; стадия L0–L5 показывает состояние инициативы. Поле `digital_layer` читается из отдельного блока `digitalLayers` по прежней строке и коду; пустое значение требует уточнения, значение из другого справочника отклоняет новый срез


## Расчёт прироста сохраняет отдельный финансовый допуск

Пустые `depreciation_source` и `depreciation_period` нормализуются в `null`. Производственный расчёт сохраняет выпуск и сравнительную оценку. Явные `incremental_assumptions` разрешают оценить изменение цены при одинаковых неизвестных расходах. Изменение физического драйвера требует соответствующие переменные ставки и полноту расходов

EBIT обозначает прибыль до процентов и налогов. Прирост EBIT равен приросту EBITDA за вычетом дополнительной амортизации того же периода. Явный ноль и отрицательная дополнительная амортизация сохраняют своё числовое значение. Финансовое согласование амортизации требует источник и полномочия согласующего

Годовой ввод `annualActualInputJSON` хранится в `Калькулятор EBITDA!K3`. Срез включает 28 блоков, версия схемы – 12. Годовые продажи мая 2025–апреля 2026 и производственный сравнительный случай января–июня 2026 сохраняют отдельные периоды. Годовая модель изменения цены требует явное сохранение расходов; управленческая маржа источника показывается отдельным контрольным фактом

Поле `action_due` передаёт дату и время с часовым поясом Москвы. Поля стадий сохраняют календарную дату. Происхождение каждой карточки включает предварительную оценку, правовые основания и статус проверки применимости закона. Предварительные числа сохраняют отдельное финансовое согласование
